# Sites

The [Sites page](https://www.respira.press/dashboard/sites) at `dashboard/sites` is your inventory of every WordPress install bridged to your Respira account. Connecting a site, renaming it, switching its automatic updates and removing it all happen here; agent keys live in MCP Setup.

## What each row shows

Each row is one connected WordPress site:

- **The site's name and URL.** Click the name, or the pencil, to rename it. The name is only for you; the URL is the site itself.
- **Status.** *Token ready* means agents can reach the site. A site that has not checked in for 14 days shows as dormant. *Needs MCP setup* means the site is linked but no agent key has been made for it yet; open MCP Setup to make one.
- **Plugin version and automatic updates.** The *Automatic updates* card above the table switches Respira's own updates on or off for each site, or for every site at once.
- **Row actions:** open the site's WP admin, manage it in MCP Setup, see what the AI remembers about the site (site memory), share access with a developer, edit the site URL, and remove the site.

Sites that belong to a team you are a member of are marked *Team site*. Only the team owner can rename or remove them.

## Adding a site

1. On the [Sites page](https://www.respira.press/dashboard/sites), press **Connect a site**.
2. Download the Respira plugin there and install it on the new site: in wp-admin go to **Plugins → Add New → Upload Plugin**, choose the file, then **Activate**.
3. In wp-admin open **Respira → Setup** and press **link this site to respira.press**. You sign in on respira.press, confirm, and land back in wp-admin with the site linked.

The Connect a site page watches for the new site and takes you back to Sites a few seconds after step 3.

If the sign-in page does not load (a firewall, a locked-down wp-admin), choose **paste a license key** in Respira → Setup instead, and paste the key from the Connect a site page (the **Copy key** button).

When every site slot on your plan is in use, the button reads **Upgrade to add a site**. Remove a site you no longer use to free a slot, or move to a larger plan under [Billing](https://www.respira.press/dashboard/billing). Full walkthrough: [Connecting Your Site](/dashboard/connecting-your-site).

## Setting up an AI app for one site

Agent keys and app setup live on [MCP Setup](https://www.respira.press/dashboard/mcp), not on this page; each row's **Manage in MCP setup** action opens it for that site.

- **Every site at once** is the default: your AI app can reach any of your sites by name. Use it when you move between sites.
- **One site only** limits an app to that site. Use it when you hand a single site to a contractor, or show the workflow on one site without the others.

## Activity on a site

Every change an agent makes is logged on the site itself. In that site's wp-admin open **Respira → Activity** for the list of changes, and **Respira → Audit Log** for every call with its agent, time and outcome. Changes with a snapshot can be undone from **Respira → Approvals & Undo**. An agent can read the same history with the activity tools.

How long the audit log is kept is a setting on each site: **Respira → Settings → Safety controls → Keep the audit log for (days)**. The default is 180 days; 0 keeps everything.

## Automatic updates

Each site has an **Automatic updates** switch, and above the list one action for every site at once. When it is on, the site installs each new Respira release by itself: Respira only, on WordPress's own schedule, never a new major version. The switch needs Respira 9.1.12 or later on the site. Details, and what a server can block, are in [Automatic Updates](/automatic-updates).

## Status states explained

**Token ready.** The site is linked and has an agent key; AI apps can reach it.

**Dormant.** The site has not checked in with respira.press for more than 14 days. It may be offline, the plugin may be deactivated, or a firewall may block its outbound requests. Open its wp-admin and check that Respira is active and up to date.

**Needs MCP setup.** The site is linked but has no agent key yet. Open MCP Setup and make one.

The filters above the table show each group on its own.

## Rotating a site's key

An agent reaches a site with that site's key. If a key may have been exposed (committed to a repository, pasted in a chat, shared with a contractor who has left the project), make a new one: open [MCP Setup](https://www.respira.press/dashboard/mcp), open the site's menu and choose **Regenerate key**. The old key stops working at once. **Revoke key** removes it without making a new one.

The configs MCP Setup gives you pick up the new key. If you wrote your own MCP config with the raw key in it, update that config by hand.

## Removing a site

Press the bin icon on the site's row. The site leaves your account, its agent key is revoked, and its slot is free again. Any AI app that used that site's key can no longer reach it.

Nothing changes on the WordPress side: the plugin stays installed and the site's content is untouched. To bring the site back, open **Respira → Setup** in its wp-admin and link it again.

## Site limits per plan

| Plan | Sites included |
| --- | --- |
| Free trial (7 days) | 1 |
| Maker | 1 |
| Builder | 5 or 10, depending on the tier you pick |
| Studio | 25 to 250, depending on the tier you pick |
| Founder | unlimited |

A staging copy is a site of its own and takes a slot. On WordPress Multisite, each subsite you connect takes one slot. If your account has more than one licence, their sites add up. The Sites table shows your current usage in the header (`X of Y connected`). Current prices for each tier are on the [pricing page](https://www.respira.press/pricing).

When you're at the cap, the *Add site* button is disabled with a tooltip pointing at [Billing](https://www.respira.press/dashboard/billing) to upgrade or stack.
