## FAQ

## Do I need coding experience to use Respira for WordPress?

No. Respira is designed so you can work entirely through natural language. Developers can go deeper, but coding is not required.

## Which AI tools work with Respira?

Respira works with AI coding assistants that support the MCP protocol, including Cursor, Claude Code, Windsurf, and similar tools.

## How many tools are available now?

Every plan includes 300+ tools: 302 on 17 November 2026. The [WooCommerce add-on](/woocommerce/overview) adds 104 more, so 400+ with the add-on (406). To keep prompts lean, the MCP server lists only the tools that fit a site's own builder and active plugins, so one site sees fewer than the whole catalog. The [tools catalog](https://www.respira.press/tools) is counted from the code on every release.

## Is it safe to let AI edit my site?

Yes. Respira uses a controlled, permission-based workflow. Your AI assistant proposes changes, and you approve them before they are applied.

## Does Respira modify content directly or create duplicates?

By default, Respira creates duplicates for safety. If direct editing is enabled, Respira asks for explicit live vs duplicate confirmation before editing originals.

## Is Respira free to try?

Yes. Respira offers a free trial. You can start without entering payment details. Respira Code is not part of the trial.

## How do I pause, cancel or get a refund?

Open [Billing](https://www.respira.press/dashboard/billing) in your dashboard. The **Pause or cancel** card pauses a monthly plan for one month or cancels it, and a cancelled plan keeps working until the end of the period you paid for. Refunds within 14 days of a payment go through [word@respira.press](mailto:word@respira.press). The details are on [Billing, pausing, cancelling and refunds](/dashboard/billing).

## Does the accessibility scanner guarantee my site is compliant?

No. The [WCAG Scanner](/dashboard/accessibility) runs Google Lighthouse accessibility audits, which use axe-core rules, and checks only the part of WCAG 2.2 that a machine can test. It is included with every paid plan, 10 scans a month. It does not guarantee legal compliance.

## What is Respira Code?

Respira Code is a paid add-on for Respira for WordPress. It lets an AI agent write a small application for your site and ship it, with a crash guard and a snapshot before every data change. It needs the Respira plugin (9.3.10 or newer) and a paid plan, and it is not available on a trial. It costs EUR 20 a month or EUR 158 a year. It is included at no extra cost on yearly Builder 10, yearly Studio and the legacy Agency plan while the 100 launch licences last, and Founder licences have it. Maker and Builder 5 do not include it. See [Respira Code](/respira-code).

## Which page builders does Respira support?

Respira supports 19 page builders: Gutenberg, Elementor, Divi (Divi 4 and Divi 5), Bricks, Oxygen (Classic and Oxygen 6), Beaver Builder, Breakdance, Flatsome, YOOtheme Pro, Avada, Brizy, Visual Composer, WPBakery, Spectra, Kadence Blocks, GenerateBlocks, GreenShift, Thrive Architect and SeedProd. All of them are read and written, except SeedProd, which is audit-only (agents read and report on landing pages), and Thrive Architect, which supports text edits.

Themes that ship their own copy of WPBakery, such as Salient, The7, Uncode and Bridge, work through the WPBakery support. See [Themes built on WPBakery](/builders/wpbakery#themes-built-on-wpbakery).

Since 8.0 "Canopy" the native WordPress Site Editor is covered too, which makes the line "19 page builders plus the native Site Editor". On a block theme that means block templates and template parts, synced and unsynced patterns, block navigation, and global styles. Read-only discovery works everywhere; structural writes to those site-level objects are beta-gated per site and off by default. See [Site Editor](/builders/site-editor).

## Does Respira work with Salient, The7, Uncode or Bridge?

Yes. These themes ship their own copy of WPBakery, and Respira detects it as WPBakery, so pages built with it are read and edited like any WPBakery page, on a copy first and with undo. Uncode's own elements are edited too. Other theme-only elements, such as Salient's Nectar elements, are kept exactly as they are, but their settings are not edited through Respira yet. If a site builds its pages with Elementor instead, which The7 and Bridge also support, Respira works through Elementor.

## I see `respira_mcp_update` in responses. Is that an error?

No. It is an upgrade hint from the MCP server when a newer package version is available. Upgrade with:

```bash
npx -y @respira/wordpress-mcp-server@latest
```

To disable automatic update checks, set `RESPIRA_MCP_DISABLE_UPDATE_CHECK=1`.

## Where did settings go after the 4.0 admin refresh?

`Respira → Settings` is now the single source of truth for editable plugin settings. `Setup → Health & Permissions` is a read-only readiness summary.

## I hit Elementor 500 errors during updates. What should I do?

Update to the latest Respira for WordPress plugin and MCP server. Recent releases include hardened payload handling, safer fallback writes, and improved structured diagnostics.
